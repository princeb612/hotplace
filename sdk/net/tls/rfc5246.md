## RFC 5246 summary

Here is a visual summary and structured overview of the major components, message flows, and specifications of the TLS 1.2 protocol as specified in RFC 5246.

### 1. High-Level Architecture & Protocol Layering

TLS is divided into two primary operational layers:
- TLS Handshaking Protocols (Higher Layer): Handshake, Alert, Change Cipher Spec, Application Data.
- TLS Record Protocol (Lower Layer): Operates over a reliable transport (e.g., TCP) to provide private and reliable communication using fragmentation, compression, MAC verification, and encryption.

```
+-----------------------------------------------------------------------+
|                       TLS Handshaking Protocols                       |
|  +------------------+  +---------------+  +------------+  +--------+  |
|  |    Handshake     |  | Change Cipher |  |   Alert    |  | App    |  |
|  |     Protocol     |  | Spec Protocol |  |  Protocol  |  | Data   |  |
|  +------------------+  +---------------+  +------------+  +--------+  |
+-----------------------------------------------------------------------+
|                          TLS Record Protocol                          |
|  (Fragmentation -> [Compression] -> MAC/AEAD -> Encryption/Protect)   |
+-----------------------------------------------------------------------+
|                    Transport Layer (TCP, etc.)                        |
+-----------------------------------------------------------------------+
```

### 3. Record Layer Processing Flow

Data emitted from higher-level protocols is processed through the Record Layer following this pipeline:

```
  Higher-Level Plaintext (App Data, Handshake, Alert, etc.)
                          |
                          v
         +---------------------------------+
         | 1. Fragmentation (<= 2^14 bytes)|
         +---------------------------------+
                          |
                          v
         +---------------------------------+
         | 2. Compression (Optional/Null)  |
         +---------------------------------+
                          |
                          v
         +---------------------------------+
         | 3. MAC Calculation & Encryption |
         |   (Stream / CBC / AEAD Mode)    |
         +---------------------------------+
                          |
                          v
                    TLSCiphertext
```

### 4. Summary of Key Concepts & TLS 1.2 Improvements

Major Differences from TLS 1.1
- PRF & Hash Flexibility: Replaced the fixed MD5/SHA-1 combination in the Pseudorandom Function (PRF) and signatures with cipher-suite-defined PRFs (defaulting to P_SHA256) and explicit hash specifications.
- AEAD Cipher Support: Added native support for Authenticated Encryption with Associated Data (AEAD) modes such as GCM and CCM.
- Signature Algorithms Extension: Added the signature_algorithms extension so the client can explicitly negotiate accepted hash/signature algorithm pairs.
- Mandatory Cipher Suite: Defined TLS_RSA_WITH_AES_128_CBC_SHA as the mandatory-to-implement cipher suite.
- Deprecated Ciphers: Deprecated IDEA and DES cipher suites.

Primary Protocol Goals
- Cryptographic Security: Establishing a secure, eavesdropping-resistant, and tamper-proof connection.
- Interoperability: Enabling independent developers to build compatible implementations.
- Extensibility: Providing a framework for adding new cryptographic algorithms and extensions.
- Relative Efficiency: Supporting session resumption to reduce CPU-heavy public key operations and network round-trips.
