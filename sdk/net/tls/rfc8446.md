## RFC 8446 summary

An overview and structured summary of RFC 8446 (The Transport Layer Security Protocol Version 1.3) are provided below.

### Protocol Flow Overview

```
       Client                                           Server

Key  ^ ClientHello
Exch | + key_share*
     | + signature_algorithms*
     | + psk_key_exchange_modes*
     v + pre_shared_key*       -------->
                                                  ServerHello  ^ Key
                                                 + key_share*  | Exch
                                            + pre_shared_key*  v
                                        {EncryptedExtensions}  ^  Server
                                        {CertificateRequest*}  v  Params
                                               {Certificate*}  ^
                                         {CertificateVerify*}  | Auth
                                                   {Finished}  v
                               <--------  [Application Data*]
     ^ {Certificate*}
Auth | {CertificateVerify*}
     v {Finished}              -------->
       [Application Data]      <------->  [Application Data]

       +  Indicates noteworthy extensions sent in the message.
       *  Indicates optional or situation-dependent messages/extensions.
       {} Protected using keys derived from [sender]_handshake_traffic_secret.
       [] Protected using keys derived from [sender]_application_traffic_secret_N.
```

### Core Summary of TLS 1.3

1. Primary Objectives & Security Properties
- Authentication: Always authenticates the server side; optionally authenticates the client side via public-key cryptography (e.g., RSA, ECDSA, EdDSA) or Pre-Shared Keys (PSK).
- Confidentiality: Protects application data from eavesdropping using AEAD encryption after establishment.
- Integrity: Prevents data tampering or forgery by active network attackers.

2. Major Architectural Differences from TLS 1.2
- Reduced Handshake Latency: Standard full handshake requires only 1 Round-Trip Time (1-RTT) compared to 2-RTT in TLS 1.2.
- 0-RTT Early Data Mode: Allows clients sharing a PSK to send application data in the very first flight, trading off forward secrecy and replay protection for speed.
- Enhanced Privacy: All handshake messages following ServerHello are encrypted.
- Pruned Legacy Features: Removed static RSA/DH key exchange (mandating Forward Secrecy), custom DHE groups, CBC-mode ciphers, compression, and insecure hashes like MD5 and SHA-1.
- Redesigned HKDF Key Derivation: Uses HMAC-based Extract-and-Expand Key Derivation Function (HKDF) for explicit key separation and cryptographic analysis.

3. Handshake Phases
- Key Exchange Phase (ClientHello, ServerHello): Establishes shared secrets, negotiates protocol version, cipher suites, and (EC)DHE key shares or PSKs.
- Server Parameters Phase (EncryptedExtensions, CertificateRequest): Configures encrypted connection attributes and optionally requests client certificates.
- Authentication Phase (Certificate, CertificateVerify, Finished): Authenticates endpoints, provides key confirmation, and binds handshake integrity.

4. Key Exchange Modes
- (EC)DHE: Ephemeral Diffie-Hellman over finite fields or elliptic curves providing Forward Secrecy.
- PSK-only: Symmetric pre-shared key mode without Diffie-Hellman.
- PSK with (EC)DHE: Pre-shared key combined with Diffie-Hellman to guarantee Forward Secrecy.
