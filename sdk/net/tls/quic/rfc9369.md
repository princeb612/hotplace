## RFC 9369

### QUIC Version 2 Overview (RFC 9369)

RFC 9369 specifies QUIC version 2, which is functionally identical to QUIC version 1 in application capabilities but modified to combat middlebox ossification and validate QUIC's version negotiation mechanisms. It establishes a blueprint for future minor protocol updates without introducing new security or application-level features.

### Core Differences from QUIC Version 1

- Wire Image Identifier: The Version field on long headers is set to 0x6b3343cf (derived from the SHA-256 hash of "QUICv2 version number").
- Long Header Packet Types: Long Header packet type bits are reassigned to differ strictly from version 1:
  - Retry: 0b00
  - Initial: 0b01
  - 0-RTT: 0b10
  - Handshake: 0b11
- Cryptographic Salt & HKDF Labels:
  - Initial Salt: 0x0dede3def700a6db819381be6e269dcbf9bd2ed9.
  - HKDF Labels: Updated to "quicv2 key", "quicv2 iv", "quicv2 hp", and "quicv2 ku".
- Retry Integrity Tag: Re-keyed using a distinct static secret, key, and nonce derived from the SHA-256 hash of "QUICv2 retry secret".
- Token & Session Isolation: TLS session tickets and NEW_TOKEN tokens are strictly single-version; v1 artifacts cannot initiate a v2 connection, and vice versa.

                      <----------------- 1-RTT [Negotiated] (Data)
