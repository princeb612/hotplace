## RFC 9000

Below is a high-level summary and structural diagramming of the provided RFC 9000 text.

### QUIC Core Protocol Overview

QUIC (RFC 9000) is a UDP-based, stateful, connection-oriented transport protocol designed to deliver low-latency, multiplexed, and secure communications. It combines cryptographic key exchanges (via TLS 1.3) with transport parameter negotiations to allow rapid establishment of secure channels and fast transmission of application data.

### Key Technical Pillars

- Stream Multiplexing:
  - Provides independent, ordered byte-stream channels on top of a single connection.
  - Eliminates head-of-line blocking across distinct streams.
  - Employs 62-bit Stream IDs categorized by initiator (Client vs. Server) and directionality (Unidirectional vs. Bidirectional).
- Flow Control & Concurrency:
  - Operates at two distinct levels: per-stream limits (MAX_STREAM_DATA) and connection-wide limits (MAX_DATA).
  - Controls maximum active stream counts using MAX_STREAMS to restrict resource allocation.
- Connection Lifecycle & ID Management:
  - Decouples transport identity from IP/port tuples using Connection IDs (CIDs).
  - Enables seamless connection migration across network changes (e.g., NAT rebinding) without breaking state.
  - Supports clean termination, idle timeouts, immediate closes, and stateless resets.
- Security & Address Validation:
  - Integrates TLS 1.3 directly to encrypt and authenticate both headers and frame payloads.
  - Mitigates Amplification Attacks by enforcing a strict 3x anti-amplification limit prior to address validation.
  - Uses PATH_CHALLENGE and PATH_RESPONSE frames to perform dynamic path liveness and MTU verification.

### Key Handshake & Migration Sequences

Standard 1-RTT Handshake Sequence:
```
Client                                                  Server
======                                                  ======
Initial [0]: CRYPTO[ClientHello] ----------------------->
                                                         Initial [0]: CRYPTO[ServerHello], ACK[0]
                                                         Handshake [0]: CRYPTO[EncryptedExtensions, Cert, ...]
                                                         <- 1-RTT [0]: STREAM [1, "0.5-RTT Data"]
Initial [1]: ACK[0]
Handshake [0]: CRYPTO[Finished], ACK[0]
1-RTT [0]: STREAM [0, "Application Data"], ACK[0] ------>
                                                         Handshake [1]: ACK[0]
                                                         <- 1-RTT [1]: HANDSHAKE_DONE, STREAM [3, "..."]

<======================== Full 1-RTT Data Exchange ========================>
```

Connection Migration & Path Validation Sequence:
```
Migrating Endpoint                                       Peer Endpoint
==================                                       =============
[New Network Path Initiated]
PATH_CHALLENGE [Unpredictable Payload] ----------------->
 (In padded >= 1200 byte datagram)

                                                         PATH_RESPONSE [Echoed Payload]
                               <------------------------  (In padded >= 1200 byte datagram)

[Path Validated: Endpoint resumes active transmission over new path]
```
