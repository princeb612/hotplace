# Base128

## 1. Role

`base128` encodes a non-negative numeric value into a variable-length sequence of 7-bit groups. Each output byte uses its high bit to indicate whether another byte follows. This representation is used, for example, when serializing ASN.1 object identifier arcs.

The API provides overloads for fixed-width numeric values and for byte/bignumber inputs. These overloads should be understood by their input and output types rather than treated as a general-purpose symmetric conversion facility.

## 2. Data Model

### Input and output forms

```text
uint64 value ────────────────> Base128 bytes

big-endian binary value ─────> Base128 bytes

bignumber value ─────────────> Base128 bytes
```

The API also has decode overloads that consume Base128 bytes. The pointer-based overloads take the input buffer, its size, and a mutable position, allowing one encoded value to be consumed from a larger buffer. The position advances as bytes are read.

The `bignumber` encoding overload represents a large numeric value in Base128 form. Do not infer from that use case that Base128 is intended to serve as a general bidirectional conversion layer for arbitrary numeric or binary data.

## 3. Behavior Model

### Encoding large values

`base128_encode(const bignumber&, binary_t&)` emits the value in 7-bit groups, setting the continuation bit on all but the final byte. This lets a large `bignumber` value be represented without first narrowing it to a fixed-width C++ integer.

The test case uses large values such as (2^{256}-1) and (2^{256}) to exercise this encoding path. It then decodes the generated bytes and compares the recovered `bignumber` with the original as a round-trip check. That assertion verifies the tested encode/decode path; it should not be read as a broader statement that every reverse conversion involving Base128 is supported or intended.

### Tests

`test/testcase/encode/testcase_base128.cpp`

The testcase covers:

- known `uint64` values and expected Base128 byte vectors;
- decoding with a position index and checking that the encoded value was consumed;
- encoding a big-endian byte representation of a value;
- encoding large `bignumber` values and checking the round-trip result.

The fixed vectors document concrete byte-level behavior. The large-number cases specifically exercise values that exceed ordinary fixed-width integer types.

## 4. Relationships

- `sdk/io/asn.1/` — ASN.1 OID handling consumes Base128 continuation-byte encoding for OID arcs. OID semantics belong to ASN.1; this module provides the numeric encoding primitive.
- `base128.hpp/.cpp` — public declarations and implementation.
- `test/testcase/encode/testcase_base128.cpp` — source-level evidence for the fixed vectors and large-number cases.
