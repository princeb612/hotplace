## Background

`sdk/io/asn.1/loader/loader-flow.md` contains a roadmap with several completed phases and remaining unchecked entries, including:

- schema-guided dynamic test-vector construction using `testvector_loader.yml`;
- PKIX schema integration based on RFC 5280 / RFC 5912;
- OpenSSL-issued X.509 interoperability comparisons;
- certificate extension and constraint handling;
- compiler linkage/code generation work.

The roadmap mixes completed implementation history, future aspirations, and potentially stale status marks.

## Current understanding

- An unchecked roadmap item is not by itself proof that the capability is absent from the current source.
- This is not an assertion that PKIX/X.509 validation or code generation is currently implemented.
- The loader, semantic module, builder, constraint evaluation, and compiler are separate layers; status should be assessed per layer rather than as one all-or-nothing “ASN.1 complete” claim.

## Historical unchecked items captured from the source document

- Schema-guided dynamic test-vector construction: write test case specifications using `testvector_loader.yml` and implement `testvector_loader.cpp`.
- PKIX standard schema integration (RFC 5280 / RFC 5912): add schemas for `TBSCertificate`, `AlgorithmIdentifier`, `SubjectPublicKeyInfo`, and extensions; verify symbol resolution.
- OpenSSL interoperability: parse OpenSSL-issued RSA/ECDSA X.509 `.crt` / `.pem` inputs and compare output with OpenSSL text dumps using `asn1_notation_visitor`.
- Certificate constraints and extension handling: KeyUsage, SAN, and OPTIONAL/CHOICE/CRITICAL fields such as BasicConstraints.
- Compiler extension: define a code-generator visitor accepting the current ASN.1 module AST; render C++11 structs including `has_field` flags for OPTIONAL fields; generate static DER TLV encoders/decoders.

The testcase README also preserved a compact unchecked checklist for ASN.1 Runtime, ASN.1 Compiler, ASN.1 Schema Loader, and ASN.1 Repository. These labels are too broad to establish current status and are retained here only as historical prompts.

These are faithfully retained as unchecked roadmap entries only. Their current implementation status must be checked before they are treated as open work.
