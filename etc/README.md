# Repository resources

## 1. Role

The `etc/` area contains repository-managed resources and environment helper scripts consumed by development, build and test workflows. It is part of the hotplace source tree, not the operating system's `/etc` directory.

The documented areas have three distinct responsibilities: certificate fixtures, generated binary parsing-table artifacts, and shell helpers for configuring supported development environments.

## 2. Model

```text
etc/
├─ cert/
│  ├─ trust/trust.crt
│  ├─ server-*.crt / server-*.key
│  ├─ server-*.der             (optional/generated fixture inputs)
│  ├─ issue.sh
│  ├─ crt2der.sh
│  └─ CMakeLists.txt
├─ parsingtable/
│  ├─ parsingtable.zip
│  └─ CMakeLists.txt
└─ script/
   ├─ env.mingw64
   ├─ env.rockylinux
   └─ env.ubuntu
```

- `cert/` stores test certificate material and scripts to generate or convert it.
- `parsingtable/` stores binary parser-table artifacts. The grammar and generator source are maintained under `test/tool/makeparsingtable/`, not as hand-edited binary content.
- `script/` provides shell functions for installing development packages, configuring shared-library search paths, and (on MinGW/MSYS) preparing runtime DLL redistribution.

## 3. Important behavior and lifetime

### Certificate distribution

`etc/cert/CMakeLists.txt` copies `trust/trust.crt` into the Authenticode applet build directory; `server-*.crt` and `server-*.key` into QUIC/TLS testcase and DTLS/HTTP/TLS applet directories; and any matching `server-*.der` files into ASN.1 testcase locations. These are build-tree copies of repository-managed inputs.

The root/server material generated by `issue.sh` is separate from the checked-in `trust/trust.crt` bundle: the script does not update that trust bundle automatically. DER conversion is a separate operation provided by `crt2der.sh`.

### Parsing-table distribution

`test/tool/makeparsingtable` generates LALR(1) and GLR table files. Its CMake post-build generation path is guarded for GNU on Windows (the documented MinGW64 development path); `etc/parsingtable/CMakeLists.txt` separately unpacks the stored `parsingtable.zip` into the build-tree parser and ASN.1 testcase directories. Do not assume every platform regenerates the tables on every build.

### Environment helpers

The files under `script/` are intended to be sourced into a shell, after which their functions can be called. The available functions differ by environment:

- `env.mingw64`: package installation, file-copy helper, runtime DLL redistribution for MSYS/Cygwin, and `PATH` setup for shared builds.
- `env.rockylinux`: package setup and `LD_LIBRARY_PATH` setup.
- `env.ubuntu`: package installation and `LD_LIBRARY_PATH` setup.

These scripts are environment-specific helpers, not a platform-independent package manager or a replacement for the root CMake build.

## 4. Example from the source build

A typical resource flow is:

```text
etc/cert/ ───────────── CMake copy ─────► build-tree certificate fixtures
etc/parsingtable/ ───── unzip ──────────► parser / ASN.1 testcase tables
grammar + makeparsingtable ─ generate ─► .ptb files ─► parsingtable.zip
etc/script/env.* ────── source + call ──► shell environment helpers
```

Examples of the shell helper entry points:

```sh
source etc/script/env.ubuntu
source etc/script/env.rockylinux
source etc/script/env.mingw64
```

Choose the script matching the active environment; these examples document the interface and do not claim that package installation or a build was run during this documentation update.

## 5. Relationships

- `sdk/io/parser/` — parser runtime and binary parsing-table format.
- `sdk/io/asn.1/` — ASN.1 parser/loader/runtime consuming grammar tables and DER certificate test data.
- `sdk/net/tls/` and `sdk/net/http/` — secure transport and server paths using certificate fixtures.
- `sdk/crypto/authenticode/` — trust certificate and PE verification example.
- `test/tool/makeparsingtable/` — parser table generator.
- `test/applet/` and `test/testcase/` — consumers of copied resources.
- Root `make.sh` and CMake configuration — build orchestration that incorporates the `etc/` subdirectories.
